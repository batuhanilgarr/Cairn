Migrate from Postman

Export your data from Postman, import the folder into Cairn, and end up with plain YAML files in Git. Here is exactly what carries over and what does not.

On this page

From Postman to files in four steps

  1. Export from Postman. Open Settings, Data, Export Data, and choose a folder. You get your collections, environments and globals as files.
  2. Import in Cairn. Choose Import and pick that folder. Every collection, environment and your globals come across in one go. Each collection gets its own folder.
  3. Read the summary. Cairn lists what it carried over and, just as important, what it could not. Nothing is dropped silently.
  4. Commit the folder. It is plain YAML now. Review it in a pull request like any other change.
3 collections (128 requests), each in its own folder.
2 environments, 5 secret values kept out of Git.
12 global variables (Settings > Variables).

9 folders with their own auth, variables or scripts.

What becomes what

In PostmanIn Cairn
CollectionA folder of *.req.yaml files
Folder auth, variables and scriptsfolder.yaml, committed, and seen by the CLI
Environmentenvironments/*.env.yaml; secret values stay in the git-ignored secrets file or the macOS Keychain
GlobalsGlobal variables on this Mac (Settings, Variables), never committed
Saved example responsesExamples stored in the request file, served by the mock server
Pre-request and test scriptsRun as they are: pm.test, pm.expect, pm.environment, pm.variables, pm.request, pm.response
OAuth 2.0, API key, bearer, basicCarried over
Form-data, file and GraphQL bodiesCarried over

What does not carry over yet

  • Digest, AWS and NTLM auth: the request is imported without auth and listed in the summary.
  • pm.sendRequest in scripts is not available in Cairn scripts. The summary points at the folders that use it.

Secrets do not follow you into Git

Literal passwords, tokens and keys in your auth settings are moved out of the files into global variables on your Mac, so nothing secret gets committed. After the import you can double-check from the command line:

$ cairn scan ./my-collection
$ cairn validate ./my-collection

The CLI is not on npm yet; see the CLI reference for how to build it.

Then run it in CI

The same collection runs headless with cairn run ./my-collection --env Staging --junit results.xml, or with the GitHub Action. Secret values on CI come from CAIRN_VAR_<name> environment variables.

Coming from Bruno or Insomnia? Bruno folders import directly, and any cURL command can be pasted into the URL bar. See also importing OpenAPI, HAR and WSDL.
