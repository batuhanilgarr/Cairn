A collection is a folder

Nothing is generated and nothing hides in a database. Keys are always written in the same order, values that equal the default are left out, and bodies and scripts are YAML literal blocks, so a change in the app is a small change in git diff. Order comes from file names, never from file contents.

my-collection/
  cairn.yaml                 marks the collection root
  folder.yaml                defaults for the root: headers, auth, scripts
  environments/
    staging.env.yaml         a set of variables
  invoices/
    folder.yaml              defaults for this folder
    create-invoice.req.yaml  one request
  .cairn/
    secrets.yaml             secret values, git-ignored

Collections made before the rename to Cairn have reqnest.yaml and .reqnest/. Both are still read. The full contract is in the file format document.

JSON Schemas for editors and CI

The format has published JSON Schemas (draft 2020-12), versioned in the URL. Within v1 keys are only added, never removed or renamed, so a file that is valid today stays valid. A breaking change would ship as /schema/v2/ with a migration.

FileSchema
*.req.yamlrequest.schema.json
folder.yamlfolder.schema.json
cairn.yamlcollection.schema.json
environments/*.env.yamlenvironment.schema.json

Editor completion in VS Code

With the YAML extension (Red Hat), add this to .vscode/settings.json in the collection for completion, hover docs and red squiggles on typos:

{
  "yaml.schemas": {
    "https://batuhanilgarr.github.io/Cairn/schema/v1/request.schema.json": "**/*.req.yaml",
    "https://batuhanilgarr.github.io/Cairn/schema/v1/folder.schema.json": "**/folder.yaml",
    "https://batuhanilgarr.github.io/Cairn/schema/v1/collection.schema.json": "/cairn.yaml",
    "https://batuhanilgarr.github.io/Cairn/schema/v1/environment.schema.json": "environments/*.env.yaml"
  }
}

Check files from the command line, or in CI and as a pre-commit hook, with cairn validate ./my-collection.

CLI reference

The CLI is the app’s engine without the window. It is not on npm yet: build it once with cd cli && npm ci && npm run build, then run node cli/dist/cairn.mjs wherever this page says cairn. It needs Node 20.

CommandWhat it does
cairn run <path>Runs a collection, folder or single request file with folder defaults, captures, scripts, assertions, OAuth client credentials and cookies. Options include --env (a comma list layers environments), --var key=value, --data, --iterations, --bail, and --junit, --json, --html reports.
cairn scan <path>Finds credentials written into committed YAML. --fail-on high narrows it to known token formats; --format json for machines. Silence a line with # cairn-ignore.
cairn validate <path>Checks files against the v1 JSON Schemas and prints file:line path message.
cairn export openapi <path>Writes OpenAPI 3.0.3 from a collection (-o api.yaml or .json, --env for the server). Credentials are never written.
cairn import har <file> <dir>Imports a browser recording. API calls only by default, --all for everything, --dry-run to see the result first.

Exit code 0 means everything passed, 1 means a test or request failed or a check found something, 2 means bad usage or configuration. Secret variables are empty on CI: supply them as CAIRN_VAR_<name> environment variables or with --var.

GitHub Action

- uses: batuhanilgarr/Cairn@main
  with:
    path: api-tests
    env: Staging
    junit: results.xml
  env:
    CAIRN_VAR_clientSecret: ${{ secrets.CLIENT_SECRET }}

Not in the CLI: browser sign-in for OAuth authorization code, and WebSocket, SSE and gRPC requests are skipped. Scripts run in a Node worker thread and are not sandboxed like in the app.
