Local-first API client for macOS

The API client that lives in your repo.

Cairn is a fast Mac app for REST, GraphQL, gRPC, WebSocket, SSE and MCP. Every request is a small YAML file you review in a pull request and run in CI. No account, no cloud, no telemetry.

Reviews that read like code reviews

Keys are always in the same order. There are no generated IDs and no sequence numbers. Bodies are literal blocks, so a changed JSON field is one changed line in the diff.

The collection is a folder. Open it in any editor, check it in, run it in CI with the CLI. If you stop using Cairn tomorrow, you still have readable files.

  • Order comes from file names, never from file contents.
  • One request can be shared by many folders with use: links.
  • The format is documented, with published JSON Schemas and cairn validate.
  • Edits made outside the app are picked up when the window regains focus.
# credentials written into the files you commit
$ cairn scan ./my-collection
# exit code 1 at "medium" or above
$ cairn scan . --fail-on high
# only known token formats, private keys, passwords in URLs
$ cairn scan . --format json

Secrets stay out of Git

Secret variables live in a git-ignored file, or in the macOS Keychain if you prefer. Imports move credentials out of the request files, and a scanner catches the ones that slip in.

  • Secret values go to .cairn/secrets.yaml, which Cairn adds to .gitignore, or to the macOS Keychain (Settings, Secrets). The CLI can read Keychain values on the same Mac.
  • cairn scan finds known token formats, private keys and literal passwords in committed YAML, shows only a masked preview, and works as a pre-commit hook or CI step.
  • Postman and HAR imports move passwords, tokens and keys into secret variables instead of the files.

The scanner reads files, not Git history: rotate a credential that was already committed. The app is not signed yet, so macOS may ask again for Keychain access after an update.

Bring what you already have

Export from Postman, pick the folder in Cairn, and every collection, environment and your globals come across in one go.

  • Each collection becomes a folder. Its folders keep their own auth, variables and scripts.
  • OAuth 2.0, API key, bearer and basic auth, form-data, file and GraphQL bodies, and saved examples are carried over.
  • Pre-request and test scripts run as they are: pm.test, pm.expect, pm.environment, pm.response.

Digest, AWS and NTLM auth and pm.sendRequest are not supported yet. The import lists everything it could not carry over.

The same collection, in CI

The CLI uses the same pipeline as the app: folder defaults, captures, scripts, assertions, OAuth client credentials and cookies.

  • run supports data-driven runs, layered environments, and JUnit, JSON and HTML reports. Exit code 0 means all passed, 1 a test failed, 2 bad usage.
  • export openapi turns a collection into OpenAPI 3.0.3, with credentials left out.
  • import har turns a browser recording into requests, with credentials kept out of the files.
  • validate checks files against the published JSON Schemas.

The CLI is not on npm yet. Build it once with cd cli && npm ci && npm run build and run node cli/dist/cairn.mjs wherever the commands above say cairn. Browser sign-in, WebSocket, SSE and gRPC requests are skipped in the CLI. Details in the CLI reference.

Ask your own model about a request

Open the panel, type a question, and the model answers with your request open in front of it: the method, URL, headers, body and, if you allow it, the last response.

  • Works with Ollama and any OpenAI-compatible server: OpenAI, OpenRouter, LM Studio, vLLM, Groq.
  • Paste the curl command you already use and the endpoint, model and token are filled in. A token is optional.
  • Credentials are hidden and {{variables}} stay unresolved. The panel shows exactly what is sent.

Questions go straight from your Mac to the endpoint you set, and nowhere else. The conversation above is an illustration.

Measured, with caveats

Fast with the files you really have

Measured in our interface benchmark on an Apple M1 with 16 GB, in Chrome, with the app talking to a stand-in for the Mac side. Real disk and network time come on top, so treat these as what the interface itself costs. We have not yet measured the packaged app end to end.

10,000-request collection
0.49 s to the first rows609 elements on screen instead of 140,774.
50 MB JSON response
0.06 s to the first linesThe window never freezes. Opening and indexing the 50 MB (5.6 million lines) takes the Rust side about 0.16 s, and searching it about 12 ms.
100 MB JSON response
0.05 s to the first linesStill no freeze: only the lines you see are drawn, whatever the size.

Filtering a 50 MB body with 467,000 rows took about 0.4 s in the same benchmark. Reproduce the interface numbers with npm run bench:ui in the repository. Numbers vary by machine.

Send

Every protocol
REST, GraphQL with schema-aware autocomplete, gRPC from reflection or .proto files including streaming, WebSocket, SSE and MCP servers.
Split view and tabs
Two requests side by side, preview tabs, drag to reorder and reopen a closed tab.
OAuth 2.0
Client credentials, authorization code with PKCE in your real browser, and password grants. Tokens refresh themselves.
Uploads
multipart/form-data with text and file fields, or a file as the raw body. Paste a curl -F command and the fields are filled in.
Params and URL in sync
Type ?a=1 and the Params table fills in; edit a row and only that part of the URL changes.

Check

Tests without code, or with it
Point-and-click assertions and variable captures, plus pre- and post-response JavaScript in an isolated sandbox. Postman scripts run as they are.
Environments that extend
Environment files can extends another, import a .env file, and layer in the CLI with --env base,staging.
Shared requests
Link one request file from many folders and collections with use:.
Mock server
Save responses as examples and serve the collection locally, with path params, templating, delays and CORS.
Folder-level defaults
Set headers, auth and scripts once on a folder. Requests inherit them, override them or switch them off.

Keep

Response filter
A jq subset or JSONPath over the response, also on responses of 50 to 100 MB.
Big responses, handled
Large bodies stay on the Rust side and are drawn as a virtual list, so they scroll and search without freezing the window, in our benchmark.
Response history and diff
Compare any two responses side by side. Binary responses preview inline, and anything can be saved to disk.
Code, live, in a side panel
The open request as cURL, fetch, axios, Python, Go, Java, Kotlin, Swift, C#, PHP, Ruby, Rust, PowerShell or HTTPie.
Made for the Mac
Native menus, a command palette, full keyboard control, light and dark themes, an interface tested with axe for accessibility, and proxy, custom CA and client certificates for corporate networks.

FAQ

Questions

What is Cairn?

Cairn is a local-first API client for macOS. Your requests are plain YAML files in a folder you keep in Git. It sends REST, GraphQL, gRPC, WebSocket, SSE and MCP requests, runs tests and scripts, and has a command-line runner for CI.

Is there a Postman alternative that works without an account?

Yes. Cairn needs no account, no sign-in and no cloud. Collections are folders on your disk. Requests go straight from your Mac to the API you call, and the only other thing that can leave your Mac is a question you ask the AI assistant, which goes to the endpoint you configured.

Is Cairn a git-friendly API client?

That is the point of it. Every request is a small *.req.yaml file with no generated IDs, keys in a fixed order and bodies as literal blocks, so a changed JSON field is one changed line in a pull request. Order comes from file names, and secrets are kept out of the files. The format is documented and has published JSON Schemas.

How do I import a Postman collection into plain files?

In Postman, open Settings, Data, Export Data. In Cairn, choose Import and pick that folder. Every collection, environment and your globals come across in one go: auth, folder-level variables and scripts, saved examples and pm.* scripts included. Digest, AWS and NTLM auth and pm.sendRequest are not supported yet, and the import lists everything it could not carry over.

Can I open OpenAPI, WSDL or HAR files?

Yes. Cairn imports OpenAPI 3 and Swagger 2 from a URL, a file or the clipboard with a preview, WSDL 1.1 services (every SOAP operation becomes a POST with a sample envelope) and HAR recordings from a browser, in the app or with cairn import har. Bruno collections and cURL commands work too. The WSDL import has been tried against WSDL files written for our tests, not against live SOAP services.

What does it cost?

Pricing and licensing are not decided yet. They will be announced on this page and in the releases. Your collections are plain files, so you are never locked in: they stay readable without Cairn.

What does it send to your servers?

Nothing. There is no account, no analytics and no telemetry, and this website loads no external scripts, fonts or trackers either. The one other thing that can leave your Mac is a question you ask the AI assistant, and it goes only to the endpoint you set.

Where are my secrets stored?

Variables marked as secret live in .cairn/secrets.yaml, which Cairn adds to .gitignore, or in the macOS Keychain if you choose that in Settings. Tokens fetched by OAuth stay in memory only. cairn scan looks for credentials written into the files you commit.

Does the AI assistant need an account or a subscription?

No. You bring the model: Ollama running on your machine or server, or any OpenAI-compatible service you already use. Cairn adds nothing in between. A token is optional, and credentials from your requests are hidden before a question is sent.

Does Cairn run on Windows or Linux?

Not yet. The app is built on Tauri, so other platforms are possible, but today it targets macOS 11 or later. The CLI already runs anywhere Node 20 does.

Can scripts access my files?

In the app, scripts run in an isolated sandbox with a time limit and cannot reach your files or secrets. The CLI runs them in a Node worker, so treat CLI scripts like the rest of your CI code.

How mature is Cairn?

Cairn is early software (version 0.3.2). The interface is tested in real Chrome against a stand-in for the native side, but we have not yet exercised the packaged app end to end, and the app is not signed with an Apple Developer ID, so macOS blocks the first launch. Keep your collections in Git, which you would do anyway.
