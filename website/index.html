Built around three ideas

◫

Local-first

No sign-in, nothing to sync by default. Your requests, environments and history stay on your machine. Secrets are kept in a git-ignored file.

⎇

Git-native

Every request is a small YAML file with stable keys and no generated IDs, so diffs are readable, reviews are real and merges are boring.

⚡

Fast and small

A Rust core and a native webview. It opens instantly, handles large responses and installs as a small native app.

Everything you reach for, built in

No plugins to hunt for. One app covers the whole request lifecycle.

REST, GraphQL, gRPC, WebSocket, SSE

One tool for every protocol. GraphQL gets schema-aware autocomplete and a docs browser; gRPC works from reflection or your .proto files, including streaming.

OAuth 2.0 that just works

Client credentials, authorization code with PKCE in your real browser, and password grants. Tokens refresh themselves; reset them when you need to.

Tests without code, or with it

Point-and-click assertions and variable captures, plus pre- and post-response JavaScript in an isolated sandbox.

Folder-level defaults

Set headers, auth and scripts once on a collection or folder. Requests inherit them, and can override or switch them off.

Import what you have

OpenAPI and Swagger (with non-destructive re-sync), Postman collections, Bruno collections and cURL. Paste a curl command into the URL bar and it just fills in.

A CLI for CI

Run any collection in your pipeline with the exact same engine. Data-driven runs, JUnit, JSON and HTML reports, and a GitHub Action.

Mock server in one click

Save responses as examples (OpenAPI imports come with them) and serve your collection locally with path params, templating, delays and CORS.

Response history and diff

Compare any two responses side by side, bodies or headers. Binary responses preview inline; save anything to disk.

Code in 14 languages

cURL, fetch, axios, Python, Go, Java, Kotlin, Swift, C#, PHP, Ruby, Rust, PowerShell and HTTPie, with variables resolved or kept.

MCP client for the AI era

Connect to Model Context Protocol servers over HTTP or a local command, explore tools, resources and prompts, call them, and read the raw JSON-RPC.

Made for the Mac

Native menus, ⌘K command palette, full keyboard control, light and dark themes, proxy and custom CA support, client certificates.

Your collection is just a folder

Open it in any editor. Review it in a pull request. Run it in CI. If you stop using Reqnest tomorrow, you still have readable files.

  • Stable key order, no IDs, no sequence numbers
  • Multi-line bodies as literal blocks, so diffs are line-by-line
  • Secrets stay in .reqnest/secrets.yaml (git-ignored)
  • Edits made outside the app are picked up live
# invoices/create-invoice.req.yaml
name: Create invoice
method: POST
url: "{{baseUrl}}/v1/invoices"
auth:
  mode: inherit
body:
  mode: json
  content: |-
    {
      "customer": "{{customerId}}",
      "amount": 12900
    }
tests:
  - kind: status
    op: eq
    value: "201"
capture:
  - variable: invoiceId
    from: json
    path: $.id
$ reqnest run ./payments --env Staging --junit results.xml

Questions

What does it cost?

Pricing is announced on this page and in the releases. Your collections are plain files, so you are never locked in: they stay readable without Reqnest.

What does it send to your servers?

Nothing. There is no account, no analytics and no telemetry. Requests go straight from your Mac to the API you are calling.

How do I move over from Postman, Bruno or Insomnia?

Collections → Import: pick a Postman collection, a Bruno folder or an OpenAPI spec. Paste any curl command straight into the URL bar.

Where are my secrets stored?

Variables marked as secret live in .reqnest/secrets.yaml, which Reqnest adds to .gitignore. Tokens fetched by OAuth stay in memory only.

Windows and Linux?

The app is built on Tauri, so other platforms are possible. Today it targets macOS. The CLI already runs anywhere Node 20 does.

Can scripts access my files?

In the app, scripts run in an isolated sandbox with a time limit and cannot reach your files or secrets. The CLI runs them in a Node worker, so treat CLI scripts like the rest of your CI code.
