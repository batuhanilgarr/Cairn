Import OpenAPI, HAR and WSDL

Specs, SOAP services and browser recordings all end up the same way: small YAML request files you can review, diff and run in CI.

On this page
  1. OpenAPI and Swagger
  2. WSDL and SOAP
  3. HAR recordings
  4. Postman, Bruno, cURL

OpenAPI and Swagger

Import OpenAPI 3 or Swagger 2 specs, JSON or YAML, from a URL, a file or straight from the clipboard. A preview shows what will be written before anything is.

  • Re-sync keeps your edits. Re-importing updates requests in place, matched by source: POST /pets. The spec owns structure, you own values: new parameters and body fields are added, your values, URLs, headers and auth are kept, and operations removed from the spec are reported, never deleted.
  • Examples from schemas. Imported operations get example responses built from their schemas, kept across re-syncs, which the mock server can serve.

Export back to OpenAPI

The other direction works too. Requests become operations, folders become tags, saved examples become responses, and auth settings become security schemes. Credentials are never written, and sensitive fields in examples become <redacted>.

$ cairn export openapi ./my-collection -o api.yaml
$ cairn export openapi ./my-collection --env Prod
$ cairn export openapi ./my-collection/invoices

gRPC, WebSocket, SSE and MCP requests cannot be described in OpenAPI and are skipped with a note.

WSDL and SOAP

Every operation of a WSDL 1.1 service becomes a POST with a ready-to-edit SOAP envelope built from the schema. SOAP 1.1 and 1.2, document/literal and rpc/literal are supported. Paste the WSDL or its link into the import dialog.

Limits: WSDL 2.0, rpc/encoded (approximated), WS-Security and MTOM are not supported. The import has been tried against WSDL files written for our tests, not against live SOAP services, so tell us on GitHub if a real one misbehaves.

HAR recordings from a browser

Save the recording in your browser (DevTools, Network, Save all as HAR) and import it in the app or from the command line. Each recording gets its own folder and an environment with {{baseUrl}}.

$ cairn import har recording.har ./my-collection
$ cairn import har recording.har ./my-collection --all
$ cairn import har recording.har . --name checkout --dry-run
  • API calls only by default; --all includes pages, scripts and images; --dry-run shows what would be imported and writes nothing.
  • Tokens, passwords, API keys and Authorization headers are moved into secret variables kept in the git-ignored secrets file. Cookies are dropped. The command never prints a credential.
  • Importing the same recording twice creates a second copy. Use --name to keep them apart.

Postman, Bruno and cURL

Postman exports import in bulk: see Migrate from Postman. Bruno collections, including environments, import as folders. Paste any curl command into the URL bar and the method, headers, body and auth are filled in, curl -F uploads included.

The CLI is not on npm yet. See the CLI reference for how to build it.
