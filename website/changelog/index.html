v0.3.2Latest

Oct 15, 2026 · Release on GitHub

  • Global secret variables in the Keychain: in Settings, mark a global variable as secret. With “Keep secret values in” set to the macOS Keychain, its value is stored there and not in the app’s settings. A secret that could not be saved to the Keychain stays where it was, so nothing is lost.
  • Imported Postman credentials are secret globals: credentials the Postman import moves out of your files are flagged secret and masked.
  • cairn import har: import a browser recording from the command line. Credentials are kept out of the written files.
  • Accessibility: the run progress bar, the run results list (now reachable with the keyboard) and the response pickers in Compare have names, and two colour contrasts now meet WCAG AA (success text in the light theme, the danger button in the dark theme).

Known limits

  • Global secrets in the Keychain apply to the app only: the CLI does not read the app’s global variables.
  • Still not exercised end to end in the packaged app: the UI tests run the interface against a stand-in for the native side.
  • Windows and Linux keychains, HashiCorp and 1Password are not done.

v0.3.1

Oct 15, 2026 · Release on GitHub

  • Split view: open two requests side by side (⌘\ or Open to the right in a tab’s menu). Each pane has its own URL bar, request and response; the pane you click takes focus. In a narrow window only the focused pane shows.
  • Secrets in the macOS Keychain: Settings, Secrets, “Keep secret values in”. Secret variable values can live in the Keychain instead of .cairn/secrets.yaml. Switching moves the open collection’s secrets, and the CLI can read them on the same Mac.
  • Filter big responses: the jq (subset) and JSONPath filter now also works on responses of 8 MB and more, where the body stays on the Rust side. On a 50 MB body with 467,000 rows a filter takes about 0.4 s in our benchmark. The Rust engine answers exactly like the one used for smaller responses (342 shared test vectors).
  • SOAP and WSDL import: every operation of a WSDL 1.1 service becomes a POST with a ready-to-edit SOAP envelope built from the schema (SOAP 1.1 and 1.2, document/literal and rpc/literal).
  • Import OpenAPI from the clipboard: paste a spec, a WSDL or a link, with a preview before anything is written.
  • Fixes: the last line of a large response could be cut off at the end of the scroll; the response status and timing now stay visible in narrow panes.

Known limits

  • Still not exercised end to end in the packaged app: the UI tests run the interface against a stand-in for the native side, and the WSDL import was tried only against WSDL files written for the tests, not against live SOAP services.
  • WSDL 2.0, rpc/encoded (approximated), WS-Security and MTOM are not supported.
  • Split view: the request/response sub-tab choice is shared between the two panes, and the split is not remembered between sessions.
  • Windows and Linux keychains, HashiCorp and 1Password are not done.

v0.3.0

Oct 15, 2026 · Release on GitHub

  • Reqnest is now Cairn: new name, logo and app icon. The bundle identifier changed (com.cairnhq.app), so this installs as a separate app and its settings start fresh; your collections are untouched. Collections made before the rename (reqnest.yaml, .reqnest/) are still read.
  • Large responses: bodies of 8 MB and more stay in the Rust side and are drawn as a virtual list, so 50 and 100 MB responses open without freezing the window; search works on any size. The 10,000-request collection tree is virtualized too.
  • Response filter: jq (a practical subset) and JSONPath over JSON responses.
  • Environments: extends: inheritance, Import .env, and layered --env base,staging in the CLI.
  • Shared requests: one request file can be linked from many folders and collections (use:).
  • Tabs: preview tab, drag to reorder, tab menu, reopen closed tab.
  • Secret scanner: Scan for secrets finds credentials in committed files and moves them into secret variables; cairn scan does the same in CI.
  • OpenAPI: export a collection as OpenAPI 3.0.3 (cairn export openapi), import from the clipboard with a preview, and import HAR recordings with credentials kept out of the files.
  • File format: published JSON Schemas (v1), a format document, and cairn validate.
  • Accessibility: axe-clean screens, modal focus handling, labels and contrast.

Known limits

  • Not exercised end to end in the packaged app: the UI tests run the interface against a stand-in for the native side.
  • The jq filter is a subset, and it did not apply to the largest (Rust-held) responses yet. That was fixed in v0.3.1.
